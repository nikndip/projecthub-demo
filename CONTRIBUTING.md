# Участие в разработке

ProjectHub Demo — самостоятельный учебный backend-срез проектов и резерва бюджета. Изменения должны сохранять его ограниченный объём и независимость от закрытой CRM.

## Предложить изменение

Для ошибки укажите воспроизведение, ожидаемый и фактический результат, версии Go/PostgreSQL и минимальный синтетический пример. Для нового поведения сначала опишите задачу в issue, чтобы согласовать её соответствие объёму demo.

Не публикуйте реальные данные клиентов, документы, токены, production-настройки или код закрытых систем. О сообщениях об уязвимостях — в [SECURITY.md](SECURITY.md).

## Подготовить pull request

1. Выполните локальный запуск из [README](README.md).
2. Внесите изменение в соответствующий слой: HTTP, application, domain или PostgreSQL.
3. Для новой логики или исправленной ошибки добавьте соразмерный тест. Изменения резерва должны сохранять проверку лимита и обновление в одной транзакции.
4. Отформатируйте изменённые Go-файлы через `gofmt` и выполните:

   ```bash
   go test -race ./...
   go vet ./...
   ```

5. В PR опишите проблему, итоговое поведение и реально выполненные проверки. Для изменений только документации проверьте команды, ссылки и соответствие реализованному API; запуск всех тестов не требуется.

Не переносите production-код или приватные конфигурации даже для небольшого исправления. Публичные примеры и тестовые данные должны быть синтетическими. Обзор полной CRM не означает, что её функции входят в scope demo.

Публичные материалы репозитория распространяются по [MIT](LICENSE); убедитесь, что у вас есть право публиковать предлагаемый вклад на этих условиях.
