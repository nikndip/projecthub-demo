# ProjectHub Demo

Самостоятельный backend на Go и PostgreSQL: проекты и конкурентно-безопасное резервирование бюджета заявками на оплату.

> Это clean-room демонстрация ограниченного бизнес-сценария. Она не содержит исходного кода закрытой CRM, production-конфигурации или данных агентства. Все примеры синтетические.

## Что реализовано

- Создание и получение списка проектов с бюджетом и резервом.
- Создание заявки с немедленным резервированием суммы.
- Транзакция PostgreSQL с `SELECT ... FOR UPDATE`: одновременные заявки не могут превысить бюджет проекта.
- Деньги в целых копейках, проверка входных данных и ограничений схемы.
- HTTP API на `net/http`, `pgx/v5`, структурированные логи, проверка доступности БД и корректное завершение сервера.
- Разделение HTTP-, application-, domain- и persistence-слоёв; unit- и HTTP-тесты.

Demo не реализует авторизацию, пользовательский интерфейс, сметы и налоги, тендеры, договоры, акты, файлы, оплату и согласование. Эти процессы описаны отдельно в [обзоре полной CRM](docs/product-overview.md), актуальном на 10 ноября 2026 года. Обзор не является спецификацией demo API.

## Запуск

Потребуются Docker и Docker Compose.

```bash
docker compose up --build
```

API доступно по адресу <http://localhost:8080>. При занятом порте:

```bash
HOST_PORT=18082 docker compose up --build
```

В следующих примерах используется стандартный порт `8080`.

```bash
curl http://localhost:8080/healthz
```

При доступной PostgreSQL ответ — `200` и `{"status":"ok"}`; при недоступной БД — `503`. Миграция применяется при запуске приложения. Данные сохраняются в Docker volume; `docker compose down` останавливает сервисы, сохраняя данные.

Demo не имеет аутентификации и предназначено для локального знакомства; подробности — в [SECURITY.md](SECURITY.md).

## Пример сценария

Создать проект с бюджетом `150 000,00 ₽`:

```bash
curl -i http://localhost:8080/api/v1/projects \
  -H 'Content-Type: application/json' \
  -d '{"name":"Демо-проект","client":"Демо-клиент","budget_kopecks":15000000}'
```

Сохраните `id` из ответа. Подставьте его вместо `1` и создайте заявку на `25 000,00 ₽`:

```bash
curl -i http://localhost:8080/api/v1/projects/1/payment-requests \
  -H 'Content-Type: application/json' \
  -d '{"purpose":"Услуги производства","amount_kopecks":2500000}'
```

Проверить резерв в списке проектов:

```bash
curl http://localhost:8080/api/v1/projects
```

Суммы передаются и хранятся в копейках: `2500000` означает `25 000,00 ₽`.

## API

| Метод | Маршрут | Результат |
| --- | --- | --- |
| `GET` | `/healthz` | Проверка доступности PostgreSQL |
| `GET` | `/api/v1/projects` | Список проектов в поле `items` |
| `POST` | `/api/v1/projects` | Созданный проект, HTTP `201` |
| `POST` | `/api/v1/projects/{id}/payment-requests` | Созданная заявка, HTTP `201` |

Ошибки возвращаются как `{"error":"..."}`: `400` — неверные данные, `404` — проект не найден, `409` — превышение бюджета. Создание проекта требует непустых `name`, `client` и положительного `budget_kopecks`; заявка — непустого `purpose` и положительного `amount_kopecks`.

При создании заявки репозиторий в одной транзакции блокирует строку проекта, проверяет остаток `budget_kopecks - reserved_kopecks`, создаёт заявку и увеличивает резерв. При ошибке транзакция откатывается. В этом срезе нет отдельного жизненного цикла оплаты или освобождения резерва.

## Разработка и проверка

Версия Go указана в [go.mod](go.mod); используется PostgreSQL 17. Для запуска без Docker настройте `DATABASE_URL` и `APP_ADDR` по [.env.example](.env.example), затем выполните:

```bash
go run ./cmd/api
```

Приложение читает переменные окружения; `.env.example` не загружается автоматически. База данных должна быть уже доступна.

```bash
go test -race ./...
go vet ./...
```

Эти проверки настроены в [GitHub Actions](.github/workflows/ci.yml). Наличие workflow не означает, что конкретный коммит уже прошёл проверки; результат смотрите в его запуске Actions.

```text
cmd/api/                    запуск приложения
internal/httpapi/           HTTP-транспорт
internal/app/               сценарии и валидация
internal/domain/            модели и ошибки
internal/store/postgres/    репозиторий и миграция
```
